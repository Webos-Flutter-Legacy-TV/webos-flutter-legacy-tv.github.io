Get started

Take an app you build with flutter-webos and run it on an older TV. To work on the project itself, see Development.

  1. Install the tools

    On Ubuntu (22.04, 24.04 or 26.04; WSL2 works) install the system packages and Node.js 20 or newer (details in Development, step 1):

    sudo apt-get install -y git git-lfs curl unzip xz-utils file pkg-config cmake ninja-build clang \
  libgtk-3-dev python3 python3-venv openssh-client
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash && . ~/.nvm/nvm.sh && nvm install 22

    Then get the SDK and its toolchains. They go into git-ignored folders inside the clone:

    git clone https://github.com/Webos-Flutter-Legacy-TV/flutter-webos.git
cd flutter-webos/legacy-webos
WEBOS_NDK_ACCEPT_EULA=1 ./setup.sh     # accepts the LG SDK License Agreement for the NDK
. ./env.sh                             # in each new shell
flutter-webos doctor -v                # "Flutter" and "webOS toolchain" must show [✓]

  2. Build

    cd my_app                              # an app created with flutter-webos create --platforms webos
flutter-webos build webos --release --legacy
    PackageFor
    build/webos/arm/release/ipk/<id>_<version>_arm.ipkwebOS 26 (LG's unchanged build)
    build/webos-compat/release/<id>_<version>_arm.ipkwebOS 5–25

    webOS 4 (opt-in, not yet tested on a TV): build with COMPAT_WEBOS4=1 flutter-webos build webos --release --legacy. That package is for webOS 4–6 only, and video placement doesn't work on webOS 4. See compatibility.

    webOS 3 (opt-in, not yet tested on a webOS 3 TV): build with COMPAT_WEBOS3=1 flutter-webos build webos --release --legacy. It includes everything the webOS 4 package adds, and is for webOS 2–6 only. On webOS 2 only apps without media or image plugins are covered.

    --legacy needs the default arm target, because older TVs run 32-bit software. To repackage an existing build without rebuilding:

    <path to flutter-webos>/legacy-webos/tools/make-compat-ipk.sh . release

  3. Configure

    Turn on Impeller: add "engine-switches" to webos/meta/flutter-conf.json, keeping the keys flutter-webos create put there, and add an empty webos/meta/compat-dual-surface file. Together they halve the GPU time per frame on webOS 6 (measurements).

    {
  "FLUTTER_HOME": "",
  "FLUTTER_TEMP_HOME": ".cache",
  "FLUTTER_APPDATA_HOME": ".data",
  "FLUTTER_DOWNLOAD_HOME": ".download",
  "FLUTTER_EXT_STORAGE_PATH": "",
  "FLUTTER_APP_LOG_PATH": "log",
  "engine-switches": {
    "enable-impeller": true
  }
}

    Optional switches, each an empty file in webos/meta/:

    FileEffect
    compat-widevine-l1Widevine at the hardware security level through the TV's own CDM and player. Research only, not for published apps: see DRM progress
    compat-dual-surfaceFaster frames, recommended; off automatically while media or an external texture is in use (see performance)
    compat-back-as-keyDeliver Back as a key event instead of a route pop
    compat-log-*Debug output in compat.log (see logs)

  4. Plugins

    LG's webOS plugins aren't endorsed implementations, so an app depends on both the plugin itself and its webOS implementation. Take the webOS side from the plugins fork, pinned to a release tag:

    dependencies:
  video_player: ^2.9.0                  # the plugin your Dart code imports
  video_player_webos:                   # its webOS implementation, from the fork
    git:
      url: https://github.com/Webos-Flutter-Legacy-TV/plugins.git
      ref: legacy-v0.1.0
      path: packages/video_player

    Your code keeps import 'package:video_player/video_player.dart';. Each package's folder name and package name are listed in the plugins repo's doc/plugin-list.md; the fork's fixes are in these:

    PluginWhy the fork
    video_playerLooping, lifecycle events, volume; keeps a moved or resized video visible
    video_player_drmStops position polling once the player is gone
    audioplayers_soloudResume after completion; seek never hangs
    flutter_secure_storagewebOS 6 has no usable key service; encrypts in the app sandbox
    webos_service_bridgeSubscription cancel errors

    The other LG plugins work unchanged. Full list on the compatibility page.

  5. Install on the TV

    With the TV in Developer Mode and registered as tv (how):

    ares-install --device tv build/webos-compat/release/*.ipk
ares-launch  --device tv <app-id>        # the "id" in webos/meta/appinfo.json
    Use the webos-compat package. flutter-webos run installs the webOS 26 package, which doesn't start on older TVs.

  6. Check it works

    • The app starts and draws; the remote's arrows and OK work.
    • Back goes back one page, and leaves the app from the first page.
    • Network, storage and each plugin the app uses.
    • Video: play, pause, seek, and the DRM type the app uses.

    If the app doesn't start, read /media/developer/apps/usr/palm/applications/<id>/compat.log on the TV. It has the app's output and the shims' messages. How to read it with Developer Mode.

What behaves differently

  • Back arrives as a route pop (as on Android), not as an Escape key.
  • Secure storage is encrypted in the app sandbox, not by a system keystore.
  • Seeking video takes 4–7 s to resume on webOS 6.
  • One video plane: two players can run, but only one picture is shown.

Before publishing

No legacy package has been submitted to LG's Content Store yet, so whether LG accepts the repackaged runtime is unknown.

The package bundles glibc (LGPL) and the GCC runtime (GPL with the runtime exception). See the licensing section of legacy-webos/README.md for what you must ship with it.

Don't ship compat-widevine-l1 in a published app. It uses the TV's Widevine CDM and player library without a licence from Google or LG, studio-licensed services are usually required to use certified clients, Google can revoke the TV's Widevine certificate, and its legal status is untested. It is for research on your own TV only; see DRM progress.

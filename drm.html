DRM progress

How LG's video_player_drm plugin plays protected video on webOS 26, what an older TV lacks, and where each route stands on webOS 6.

Last updated 21 November 2026 (software route removed). Tested on an LG C1 with webOS 6.5.3.

How it works on webOS 26

The plugin itself is simple. The TV's media server does almost all the work. This section is based on LG's plugin source; the media server's inner steps are inferred, not traced on a webOS 26 TV.

  1. Window. The Flutter embedder creates an exported window, a place on screen for a hardware video layer, with an id such as _Window_Id_3.
  2. Bind. The plugin calls NDL_MediaInitWithWindowId(windowId).
  3. Load. The plugin calls NDL_MediaLoadWithOption(url, option). The option carries appId, windowId and drm: {type, licenseUrl, useLicenseCallback}.
  4. Licence. With a licence URL, the media server fetches the licence itself. With a licence callback, it sends a drmEncrypted event with the challenge; the plugin asks the Dart side (requestDrmLicense) and returns the licence through NDL_MediaSetDrmOperation(..., "update", ...).
  5. Decrypt and decode. The media server downloads the stream, decrypts on the secure video path and decodes in hardware.
  6. Display. The media server connects the decoder output to the exported window. The embedder places that window where the VideoPlayer widget is and leaves a transparent hole in the UI.
  7. Events. loadCompleted, playing, currentTime, videoInfo and the rest go back to the plugin through the NDL event callback.

On webOS 6, LG's own apps get Widevine another way: web apps use the browser's built-in DRM in LG's Chromium, and the YouTube app calls the CDM and the TV's player library directly. The media path that Flutter apps use has no Widevine.

Widevine on webOS 6

Hardware route (L1)

Experimental, research only Switch compat-widevine-l1. Not for published apps (see the warning below). On main, not in a release yet: compat/widevine-l1.

Takes the same approach as the YouTube app: the TV's hardware CDM wrapper packs each sample for the secure video path, and the TV's player library (StarfishMediaAPIs) decodes it. The video is never decrypted inside the app.

Our own code reads the DASH manifest and MP4 segments and sends the plugin the same events it gets from the media API.

Software route (L3): removed

Removed 21 November 2026.

An earlier route used the TV's software CDM to decrypt the media inside the app and served it clear on 127.0.0.1 for the old media pipeline. While it played, decrypted video sat outside any protected path. That works against the protection the content owner chose, so it was removed. The project does not decrypt content outside the TV's secure hardware.

How the picture reached the screen

The hardware route first played with sound only: the test passed because the position kept advancing, but the screen stayed black. NDL's video is drawn above the app by the compositor; this route's video sits under the Flutter UI, so the video widget's transparent hole has to reach the screen.

  1. Place the video. The player tells the TV's video output service where to show it (display/setDisplayWindow, with the player's media id), as the YouTube app does.
  2. Redraw after the TV applies it. The player subscribes to display/getApplyDoneWindowRegion and asks the app for a new frame on each update, so the app's surface is committed after the video area is in place.
  3. Redraw whole frames while a video is loaded. The Wayland shim reports buffer age 0, so the embedder no longer redraws only what changed. With this Mali driver's buffer age, that left the hole in one buffer only, and the next frame brought the black back.

Found by comparing with YouTube's app (recording its calls on the TV's service bus), with Kodi's webOS player source, and by disassembling the embedder's exported-window code to list its compositor requests. The plugin needed no change.

Research use only. Do not ship the hardware Widevine route in a published app.

  • Not licensed: it uses the TV's Widevine CDM and LG's player library from an app that neither Google nor LG has licensed to use them. That is outside Google's Widevine licensing and very likely outside the TV's software terms.
  • Studio contracts: services that carry studio content usually have to use certified clients, so shipping it can also break their content contracts.
  • Revocation: Google can revoke the TV's Widevine device certificate, which would break Widevine in every app on that TV.
  • Untested in law: whether using or distributing it is lawful (for example under DMCA section 1201) has not been tested in court.
  • What it does keep: content protection. Video is decrypted only in the TV's secure hardware, and nothing decrypted leaves the player.

Use it only to test on your own TV, with content you are entitled to play. Get legal advice before anything else.

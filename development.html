Start development

Everything you need to work on the project: host machine, toolchains, a TV to test on, then the shims, plugins, test apps and pull requests. Plan about an hour for the first setup; most of it is downloading.

  1. Host machine

    A Linux x86_64 machine: Ubuntu 22.04 or newer, Debian 12 or newer, or similar. WSL2 on Windows works for building. Leave about 15 GB of free disk space for the toolchains and builds.

    # Debian / Ubuntu
sudo apt install git curl xz-utils dpkg-dev python3 python3-venv nodejs npm cmake build-essential openssh-client

    That is the only step that installs anything system-wide. Everything else goes into git-ignored folders inside the clone.

  2. Fork and clone

    Fork flutter-webos (and plugins if you'll change a plugin) on GitHub, then clone your forks side by side:

    mkdir -p ~/webos-dev && cd ~/webos-dev
git clone https://github.com/<you>/flutter-webos.git
git clone https://github.com/<you>/plugins.git
cd flutter-webos
git remote add org https://github.com/Webos-Flutter-Legacy-TV/flutter-webos.git

    The compatibility work lives in flutter-webos/legacy-webos/. The rest of the repo is LG's flutter-webos CLI.

  3. Download toolchains

    cd ~/webos-dev/flutter-webos/legacy-webos
WEBOS_NDK_ACCEPT_EULA=1 ./setup.sh

    setup.sh fetches into toolchains/ and downloads/:

    ComponentUsed for
    webosbrew buildroot-nc4 toolchainBuilding the shims against glibc 2.12, so they load on every webOS release
    Debian armel glibc (checksums verified)The C runtime bundled into legacy packages
    patchelf (Python venv)Rewriting the app's ELF interpreter and library paths
    webOS CLI (ares-*, local npm install)Packaging, installing and launching on a TV
    LG webOS NDK 11.2.0Required by flutter-webos to build apps
    Licence: the LG webOS NDK is covered by the LG SDK License Agreement. Setting WEBOS_NDK_ACCEPT_EULA=1 means you accept it. Without the variable, every other component is still installed and the NDK is skipped.

    Re-running setup.sh is safe: it skips anything already present and rebuilds the shims.

  4. Shell environment

    Source this in every new terminal:

    . ~/webos-dev/flutter-webos/legacy-webos/env.sh

    It puts flutter-webos, the ares-* tools and patchelf on PATH and points flutter-webos at the NDK. To make it permanent, add the line to ~/.bashrc.

  5. Check the setup

    command -v flutter-webos ares-install patchelf
ls legacy-webos/compat/*/out/          # the shims setup.sh built
flutter-webos --version                # first run builds the CLI snapshot (a minute or two)

    All three commands should resolve and the out/ folders should contain .so files.

  6. Build a first app

    cd ~/webos-dev
flutter-webos create hello_tv
cd hello_tv
flutter-webos build webos --release --legacy

    You get two packages: build/webos/arm/release/*.ipk for webOS 26, and build/webos-compat/release/<app-id>_<version>_arm.ipk for older webOS.

  7. Prepare a TV

    Choose one of these. Developer Mode works on any TV. A rooted TV gives SSH access, which the automated test tools use.

    Option A: Developer Mode

    1. Create a free account at webostv.developer.lge.com.
    2. On the TV, install Developer Mode from the LG Content Store and sign in.
    3. Turn on Dev Mode Status and let the TV restart.
    4. Turn on Key Server and note the IP address and passphrase shown in the app.

    Option B: Rooted TV

    On firmware where rooting is possible, install the Homebrew Channel (see webosbrew.org) and enable SSH. Put your key at ~/.ssh/lg_webos, or set TV_SSH_KEY.

    Rooting is at your own risk and may void your warranty.

    For Developer Mode, register the TV with the CLI once:

    ares-setup-device --add tv --info "{'host':'<TV IP>','port':'9922','username':'prisoner'}"
ares-novacom --device tv --getkey      # enter the passphrase from the Developer Mode app
ares-device --device tv --system-info  # should print the TV's model and webOS version
    The Developer Mode session expires after a while. Open the app on the TV and extend it before it runs out, or your installed test apps are removed.

  8. Install and run

    # Developer Mode
ares-install --device tv build/webos-compat/release/*.ipk
ares-launch  --device tv <app-id>

# Rooted TV
export TV_HOST=<TV IP>
../flutter-webos/legacy-webos/tools/tv-install.sh build/webos-compat/release/*.ipk --launch

    The app should appear on the screen. Check that the remote's arrows, OK and Back work.

  9. Logs and debug switches

    Legacy builds write the app's stdout and stderr, plus the shims' messages, to compat.log next to the installed binary:

    /media/developer/apps/usr/palm/applications/<app-id>/compat.log

    To turn on extra output, add an empty file to the app's webos/meta/ folder and rebuild:

    FileLogs
    compat-log-pmlogPlugin PmLog messages (they don't reach the system log from the app jail)
    compat-log-ndlRaw media (NDL) events
    compat-log-swapFrame timing: GPU time, swap waits, buffer releases
    compat-log-exportedVideo window placement requests
    compat-log-globals, compat-log-keysWayland globals and raw key codes

    On a rooted TV, tools/dev-cycle.sh <app> [seconds] --luna packages, installs, launches and prints compat.log in one go.

  10. Run the test apps

    Each app in legacy-webos/tests/ runs its checks on start and appends [X] name PASS|FAIL|INFO detail lines to compat_results.log in the app folder.

    AppCovers
    compat_testStartup, rendering, networking, storage; frame timing scenes with compat-perf
    input_testRemote keys, Back, focus
    plugins_testOne check per LG plugin
    video_testvideo_player: play, seek, rate, resize, two players, Home/resume
    drm_testHLS/DASH, PlayReady, opt-in Widevine
    soloud_testaudioplayers_soloud: formats, controls, mixing
     
    cd legacy-webos/tests/plugins_test
flutter-webos build webos --release
cd ../.. && TV_HOST=<TV IP> tools/dev-cycle.sh tests/plugins_test 120 --luna

    With Developer Mode, build with --legacy, install with ares-install, launch the app, then read the log with ares-shell or from the app's own screen.

  11. Work on the shims

    FolderWhat it does
    compat/wayland-shimMissing Wayland functions, protocol version clamping, Back key, EGL frame pacing, dual surface
    compat/ndl-sdl-shimStand-in libSDL2 that maps webOS 26 media calls onto the old NDL and DRM APIs
    compat/wayland-egl-forwardForwards libwayland-egl.so.1 to whichever version the TV ships
    compat/widevineOpt-in Widevine CDM proxy
    tools/make-compat-ipk.shThe packager: bundles the runtime, patches ELF files, adds the shims
     
    tools/build-shims.sh                   # rebuild after editing a shim
tools/make-compat-ipk.sh ../my_app release   # repackage an existing build without rebuilding the app
    Rules for shim changes: build against the webosbrew toolchain only (never the NDK's glibc). Put new behaviour behind an opt-in webos/meta/compat-* switch until it has been verified on a TV. Never copy code from GPL projects. Reading them for ideas is fine.

  12. Work on a plugin

    Point the test app (or your own app) at your local plugins checkout instead of the git dependency:

    # pubspec.yaml
dependencies:
  audioplayers_soloud:
    path: ../../../../plugins/packages/audioplayers_soloud
    flutter-webos pub get
flutter-webos build webos --release --legacy

    Native plugin code is under packages/<plugin>/webos/. Switch the dependency back to the git form before committing the app. To print debug output from native code, write to stderr; it ends up in compat.log.

  13. Check other releases

    Without the right TV, you can still check which libraries and functions a build needs that a firmware is missing:

    tools/fw-compat-check.py --db <fw-symbols data dir> build/webos/arm/release/bundle/lib/*.so

    The symbol data comes from webosbrew's firmware inventory. The check can't see kernel, Wayland protocol or GPU driver behaviour, so real TVs still have the final word.

  14. Send a pull request

    git checkout -b fix/short-description
# ...edit, build, test...
git commit                              # say why the change is needed
git push -u origin fix/short-description
# open the pull request against Webos-Flutter-Legacy-TV/flutter-webos main
    • Fill in the pull request template, including which TV and webOS release you tested on (or "not tested on a TV").
    • Leave out personal data: TV IP address, serial number, MAC address, accounts.
    • Keep existing licence headers. New files use BSD-3-Clause.
    • Update legacy-webos/README.md or the porting guide if behaviour changes.

    More detail is in Contribute and CONTRIBUTING.md.

Troubleshooting

SymptomFix
No bundle at .../build/webos/arm/release/bundleRun flutter-webos build webos --release before make-compat-ipk.sh or dev-cycle.sh.
webosbrew toolchain missingRun ./setup.sh again; the download may have been interrupted.
flutter-webos can't find the NDKRe-run setup.sh with WEBOS_NDK_ACCEPT_EULA=1, then source env.sh.
flutter-webos shows old behaviour after a CLI changeThe CLI snapshot is rebuilt only when git HEAD changes. Commit (or amend) to refresh it.
App installs but exits at onceRead compat.log. A missing symbol there means a firmware difference: run the firmware check.
Large install times out on a rooted TVtv-install.sh waits up to 180 s; raise TV_INSTALL_TIMEOUT for very large apps.
Moved or resized video stays blackUse the plugins fork (7a53a97 or later) with Impeller.
